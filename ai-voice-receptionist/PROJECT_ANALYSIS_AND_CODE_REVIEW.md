## 1. Executive Summary & Project Mission

**MediSlot** is an AI-driven virtual receptionist and notification platform engineered specifically for healthcare outpatient departments and hospitals. Its primary mission is to automate inbound patient phone calls and chat interactions for appointment scheduling, doctor availability inquiries, hospital FAQs, and triage-safe human handoffs.

### Key Architectural Tenet
**MediSlot does not reinvent the hospital management wheel.**  
The module owner integrates with an authoritative Hospital Management System (HMS) backend (developed via Akhil’s n8n webhook workflow / TypeScript-Express scheduling API). MediSlot acts as an intelligent, conversational, and fault-tolerant adapter between callers and the HMS.

### Non-Negotiable Healthcare Principles
1. **Zero Hallucination:** Schedules, doctor availability, and appointment references are never generated by LLM creativity; they originate strictly from verified HMS REST responses.
2. **Two-Stage Confirmation Gate:** Booking operations require an explicit two-step protocol (`prepare_booking` -> live slot check -> read-back -> `book_appointment` requiring an explicit affirmative utterance on a new turn).
3. **Pessimistic Failure Handling:** If a booking request encounters a timeout or 5xx server error, the outcome is marked `uncertain`, never blindly retried, and flagged for human staff review.
4. **Clinical Guardrails:** The system explicitly refrains from diagnosis, medical advice, prescription generation, and emergency triage, automatically diverting emergencies to emergency hotlines (112).

## 4. Safety & Healthcare Guardrails Audit

### 1. Clinical Boundaries & Emergency Protocol
- **Implementation:**  
  In `app/services/receptionist_service.py`, regex `_EMERGENCY` scans raw user text **before the LLM is ever invoked**:
  ```python
  _EMERGENCY = re.compile(r"\b(chest pain|can'?t breathe|cannot breathe|difficulty breathing|not breathing|unconscious|"
                          r"heart attack|stroke|severe bleeding|bleeding heavily|overdose|suicid\w*|seizure|"
                          r"choking|emergency)\b", re.I)
  ```
  If matched, the LLM is bypassed completely, and an immediate response is spoken directing the caller to **112** or nearest ER.
- **System Prompt Guard:**  
  Explicitly forbids diagnostic reasoning: *"NEVER give diagnosis, prescriptions, treatment advice or emergency triage."*

### 2. Transparent Identity & Privacy Protection
- **AI Identity:** Declared in greeting (*"virtual AI receptionist"*).
- **Sensitive Data Minimization:**  
  The system never asks for payment info, passwords, or national IDs. Phone numbers in logs and summaries are masked using regex (`+91******10`).
- **Transcript Purging:**  
  `RETAIN_TRANSCRIPTS=false` (in `.env`) causes `CallRepository.complete()` to erase all user/assistant dialogue messages from `calls.state_json` upon call completion, preserving only high-level anonymized summary metadata.

### 3. Patient Identity Matching for Cancellations
- **Zero Exposure of Unauthorized Appointments:**  
  HMS does not expose a global patient search API over the phone. Therefore, `AppointmentService.verify_cancellation()` checks against MediSlot’s local verified booking database requiring exact matching of:
  - `appointment_id`
  - Normalized `patient_phone`
  - Case-insensitive `patient_name`
- If unverified, the AI does **not** disclose booking details or cancel the slot; instead, it logs an escalation in `callbacks` for human hospital staff review.

### 4. Technical Fail-Safes & Interruption Handling
- **Silence & Noise Handling:** `handle_silence()` counts misunderstandings. If >= 3 consecutive silent/unintelligible turns occur, it gracefully transfers to a staff callback.
- **Bounded Tool Loop:** `MAX_TOOL_CALLS_PER_TURN=5` prevents infinite recursive LLM function calling loops.
- **Provider Outage:** `HMSUnavailable` (network down) and `HMSOutcomeUnknown` (timeout on write) fail cleanly into staff alert mode without retrying writes.

## 7. Code Quality & Architectural Review

### Strengths
- **Clean Architecture:** Strict separation between Webhook Transport -> Service Layer -> Domain Tools -> Persistence Repositories.
- **Defensive Error Handling:** `HMSOutcomeUnknown` ensures network timeouts are never blindly retried, eliminating unintentional duplicate bookings.
- **Privacy by Design:** Transcript purging, log redaction of E.164 phone numbers and API keys.
- **Provider Neutrality:** Base abstraction classes (`TelephonyProvider`, `EmailProvider`, `SMSProvider`) ensure switching from Twilio to Exotel or AWS SES is purely a matter of adding a driver class without rewriting business logic.

### Architectural Risks to Address for Production
1. **In-Memory Rate Limiting:** `RateLimitMiddleware` stores sliding-window timestamps in a local Python dictionary. If scaled across multiple Uvicorn worker processes or containers, rate limiting must be backed by Redis.
2. **Database Concurrency:** SQLite in WAL mode is efficient for single-worker prototyping, but high-concurrency telephony webhooks with concurrent transactions should transition to PostgreSQL (`psycopg[binary]`).
3. **Turn-based Latency vs Streaming:** Twilio `<Gather input="speech">` requires the caller to finish speaking, wait for Twilio STT to transcribe, post a webhook, wait for LLM completion, and generate TwiML `<Say>`. While reliable and simple, upgrading to Twilio Media Streams + WebSocket STT/TTS in the future will achieve natural conversational interruption and lower latency.
